# 参考 DOCX 版式

## 1. 基准文件与分析方法

开发机项目根目录 `template/` 中的既有支撑材料 DOCX 是首版默认输出样式的本地基准。该目录可能包含真实个人材料，已被 `.gitignore` 排除，不随源码或安装包分发。缺少本地模板不影响应用构建、测试或运行。

首次分析时没有只读取 Word 的文档属性，而是使用 LibreOffice 将文件完整渲染为 PDF，再检查页面尺寸、封面、目录、正文首页、页脚和 DOCX XML。

实际观测结果：

- 渲染后共 274 个物理页面。
- 每页均为 A4，约 595.30 × 841.89 point。
- 正文页面边距约为 12.7 mm。
- 封面后有一张不计页码的空白背页，目录从下一张纸开始。
- 目录标题为“支撑材料目录”，使用黑色多级条目、缩进和点引导线。
- 分类标题、材料标题与首张证据材料位于同一个 A4 页面，而不是默认各占一张装饰页。
- 正文页码位于底部居中，格式为 `— 1 —`。

## 2. 软件中的默认映射

新建项目默认采用以下规则：

1. 封面标题使用约 36 pt 的正式中文字体，标题上下保留细蓝线。
2. 姓名、单位、用途和日期仍显示在封面中，因为这些字段属于产品明确要求；参考文件中没有显示的字段不会被软件删去。
3. 默认插入封面背面空白页，可在项目属性中关闭。
4. 目录标题默认为“支撑材料目录”，一级、二级和材料条目使用不同缩进。
5. 新建一级目录默认不生成独立分类页。
6. 一级目录、二级目录和材料标题在第一次出现时叠加到该材料首张 A4 内容页上方。
7. 用户仍可为指定目录或材料启用独立标题页；启用后同级标题不会在内容页重复。
8. 正文页码默认使用 `— 1 —`，封面、空白背页和目录默认不计逻辑页码、不显示页码。

## 3. PagePlan 约束

`PlannedPage.inlineHeadings` 保存该物理页需要绘制的分级标题。标题不是导出末端临时推断，而是 PagePlan 的正式字段，因此：

- 缩略图卡片能够显示该页是否包含同页标题。
- 父目录起始页从第一个启用的后代材料回推。
- 目录页码、预览顺序和最终导出使用同一结果。
- 独立分类页或材料标题页启用时，同级同页标题会自动去重。

封面背面空白页使用稳定页面 ID `blank:cover-back`，不具有逻辑页码，也不会打印页码。

## 4. 中文字体

Chromium 打印优先使用系统宋体回退链。后台 `pdf-lib` 绘制同页标题和页码时使用随应用分发的 SupportPack Sans SC Regular/Bold。

这两个 TTF 是从官方 Noto Sans SC 可变字体固定为 400、700 字重后生成的静态实例，并修改了主字体名称。测试发现原始 CFF OTF 经 fontkit 子集化后会在 PDF.js 和 Poppler 中产生无效字体警告和字距异常；CJK TTF 子集化也会遗漏部分字形。因此后台采用完整字体嵌入，优先保证所有中文标题和页码可读。字体来源、版本、哈希和许可证见 `THIRD_PARTY_LICENSES.md`。

## 5. 明确保留的差异

- 软件保留姓名、单位、用途和日期，避免为了视觉相似而破坏封面字段需求。
- 软件的数据层级为一级目录、二级目录、材料三级，参考文件主要表现为分类与材料两级；因此软件会按实际项目结构生成最多三级同页标题。
- 软件不会复制参考文件中的个人信息、正文图片或具体材料，只复用经过归纳的排版规则。
- 独立标题页、封面空白背页和同页标题都可以由用户关闭，项目不会被锁死为单一模板。

## 6. 验证

模板样式回归同时检查：

- PagePlan 中的同页标题、空白背页和破折号页码。
- 隐藏 BrowserWindow 生成的真实封面与目录。
- utilityProcess 导出的每个物理页面均为 A4。
- `/SPackInlineHeadings` 与 `/SPackPageNumberLabel` 标记和 PagePlan 一致。
- PDF.js 与 Poppler 均可渲染中文标题和页码。
- 目录条目在取消独立分类页后仍能从后代材料正确回推起始页。
